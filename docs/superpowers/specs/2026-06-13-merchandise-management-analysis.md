> 日期：2026-06-13

## 一、商品管理全景图

一个完整的商品管理系统不只是"增删改商品"，而是一个涵盖**商品全生命周期**的体系，包括从供应商采购、商品信息录入、定价、上架销售、库存管理、订单履约、售后服务到数据分析的完整链条。

```
┌─────────────────────────────────────────────────────────────────────┐
│                        商品管理系统                                     │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐     │
│  │基础信息 │ │SKU/规格 │ │ 库存    │ │ 价格    │ │ 多媒体  │     │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘     │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐     │
│  │上架管理 │ │ 评价    │ │ 搜索    │ │ 供应商  │ │ 数据分析│     │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘     │
└─────────────────────────────────────────────────────────────────────┘
```

## 二、各模块详细分析

### 2.1 商品基础信息管理

这是最基础、最核心的模块，定义"商品是什么"。

| 字段 | 说明 | 现有状态 |
|------|------|----------|
| 商品名称 | 商品标题，搜索和展示的核心 | ✅ 已有 |
| 商品描述 | 图文详情介绍 | ✅ 已有 |
| 品牌 | 所属品牌（可关联品牌表） | ❌ 缺少品牌管理 |
| 商品编号/货号 | 商家自定义编码，便于内部管理 | ❌ 缺少 |
| 分类 | 归属分类，支持多级树结构 | ✅ 已有 category 服务 |
| 标签 | 自定义标签（新品、热销、推荐等） | ❌ 缺少 |
| 计量单位 | 件/个/斤/箱等 | ❌ 缺少 |
| 重量/尺寸 | 物流计费依据 | ❌ 缺少 |

**补充分析**：商品分类应当支持"前台分类"和"后台分类"两套体系——后台分类用于管理，前台分类用于展示。还需要支持分类的 SEO 优化（标题、关键词、描述），你现有 category 表已经包含了 seo_title/seo_keywords/seo_desc 字段，这点做得很好。

---

### 2.2 SKU / 规格管理

SKU（Stock Keeping Unit）是**库存管理的最小单元**，一件商品可以有多个 SKU。

```
商品：T恤
├── 规格组1：颜色 → 红色、白色、黑色
├── 规格组2：尺寸 → S、M、L、XL
└── 生成的 SKU：
    ├── SKU1：红色-S     ¥99  库存200
    ├── SKU2：红色-M     ¥99  库存180
    ├── SKU3：白色-S     ¥99  库存150
    └── ...（共12个SKU）
```

| 功能点 | 说明 | 现有状态 |
|--------|------|----------|
| 规格组管理 | 颜色、尺寸、版本等规格维度 | ✅ 已有 spec_group |
| 规格值管理 | 红色、S码等具体规格值 | ✅ 已有 spec_value |
| SKU 编码 | 自动生成唯一 SKU 编码 | ✅ 已有 sku_code |
| SKU 价格 | 不同规格可设置不同价格 | ✅ 已有 |
| SKU 图片 | 不同规格可上传不同图片 | ❌ 缺少 |

**补充分析**：现在的 spec_group 和 spec_value 设计已经很完善了。但缺少一个功能——**规格组合的图形化界面**，方便运营人员在后台快速创建规格组合，而不是手动拼 JSON。

---

### 2.3 库存管理

这是**最复杂也最容易出问题**的模块，直接关系订单履约。

| 功能点 | 说明 | 现有状态 |
|--------|------|----------|
| 基础库存 | total(总量) / available(可用) / reserved(预留) | ✅ 已有 |
| 库存预留 | 下单时预留库存，防止超卖 | ✅ 已有 |
| 库存扣减 | 支付后正式扣减 | ✅ 已有 |
| 库存释放 | 取消订单后释放预留 | ✅ 已有 |
| 库存返还 | 退款后返还库存 | ✅ 已有 |
| 乐观锁 | version 字段防止并发问题 | ✅ 已有 |

**但缺少的**：

| 缺少的功能 | 为什么重要 |
|------------|-----------|
| **库存流水** | 每次库存变动都要记录日志（谁、什么时间、什么操作、变动了多少），用于排查问题和对账 |
| **库存预警** | 当可用库存低于阈值时，通知运营人员补货 |
| **入库/出库单** | 采购入库、退货出库等操作需要单据流程，不能直接改库存数字 |
| **多仓库** | 如果有多个物理仓库，需要按仓库拆分库存 |
| **安全库存** | 保留一部分库存不销售，应对突发需求 |

---

### 2.4 价格管理

价格是商品管理的核心，涉及多种价格策略。

| 价格类型 | 说明 |
|----------|------|
| **市场价/原价** | 商品标价，用于显示"原价XXX" |
| **销售价** | 实际售价 |
| **会员价** | 特定用户等级的专享价 |
| **阶梯价** | 买越多越便宜（如买3件单价90，买5件单价80） |
| **活动价** | 参与促销活动时的临时价格 |
| **成本价** | 进价/采购成本，仅内部可见 |

**需要补充的**：
- **价格历史记录**：每次调价记录原因和时间，便于追溯
- **价格计算引擎**：会员价、活动价、优惠券叠加时的计算优先级

---

### 2.5 多媒体管理

| 功能点 | 说明 | 现有状态 |
|--------|------|----------|
| 商品主图 | 列表页展示的首图 | ✅ 有 image 字段，但只支持单图 |
| 商品轮播图 | 详情页多图轮播 | ❌ 缺少多图支持 |
| 规格图 | 不同规格对应不同图片 | ❌ 缺少 |
| 详情图 | 图文详情中的图片 | ❌ 缺少 |
| 商品视频 | 展示视频 | ❌ 缺少 |
| 图片裁剪/压缩 | 适应不同展示场景 | ❌ 缺少 |

一个商品应该支持**多张图片**，且有主图、附图之分。图片需要区分不同尺寸（缩略图/中等图/原图）。

---

### 2.6 上架/下架管理

| 功能点 | 说明 |
|--------|------|
| **上下架控制** | 前台展示状态（已上架/已下架） |
| **定时上架** | 预售场景，提前录入商品信息，到时间自动上架 |
| **定时下架** | 活动结束后自动下架 |
| **分渠道上架** | 只在某些渠道销售（小程序/APP/PC） |

你的 product 表已经有 status 字段（0下架/1上架），但缺少定时上下架和分渠道控制。

---

### 2.7 评价管理

| 功能点 | 说明 |
|--------|------|
| 评价内容 | 文字评价 |
| 评价图片 | 晒图 |
| 评分 | 1-5星 |
| 追评 | 首次评价后的补充 |
| 回复 | 商家回复 |
| 标签 | 系统自动提取的评价标签（如"质量好""发货快"） |

**评价的用途**：
1. **用户决策参考**：帮助其他买家判断商品质量
2. **商品质量反馈**：差评率高的商品需要关注
3. **搜索权重**：好评率影响搜索排序
4. **运营优化**：从评价中提取用户关注点

---

### 2.8 商品搜索与筛选

| 功能点 | 说明 |
|--------|------|
| 关键词搜索 | 按商品名称/描述搜索 |
| 分类筛选 | 按商品分类浏览 |
| 属性筛选 | 按规格/品牌/价格区间筛选 |
| 排序 | 综合/销量/价格/新品/好评 |
| 搜索建议 | 输入时自动补全 |
| 搜索结果高亮 | 匹配关键词高亮显示 |

目前你的商品搜索应该是基于 MySQL LIKE 查询，对于小规模电商够用。如果商品数量超过几万，建议引入 Elasticsearch。

---

### 2.9 供应商管理

| 功能点 | 说明 |
|--------|------|
| 供应商信息 | 名称、联系人、联系方式、地址 |
| 供货关系 | 哪个供应商提供哪些商品 |
| 采购价 | 不同供应商对同一商品的供货价 |
| 供货周期 | 从下单到到货的时间 |
| 供应商评级 | 质量/交期/配合度评估 |

目前你的系统**完全没有供应商模块**。如果平台涉及自营采购，这是必须的。

---

### 2.10 数据分析

| 功能点 | 说明 |
|--------|------|
| 商品浏览量/访客数 | 商品详情页的 UV/PV |
| 销量统计 | 按日/周/月统计每个 SKU 的销量 |
| 转化率 | 浏览次数 -> 加入购物车 -> 下单 -> 支付 的转化漏斗 |
| 库存周转率 | 库存消耗速度 |
| 商品排行榜 | 销量榜/好评榜/热搜榜 |
| 滞销商品 | 长时间无销量的商品 |

## 五、数据流 — 从商品发布到售出

```
1. 运营录入商品信息
   ├── 选择分类
   ├── 填写基本信息（名称、描述、品牌、标签）
   ├── 上传图片
   └── 配置规格（颜色/尺寸）→ 自动生成 SKU

2. 设置价格和库存
   ├── 各 SKU 独立定价
   ├── 录入初始库存 → 生成入库单
   └── 设置库存预警阈值

3. 上架（手动或定时）
   └── 商品变为"已上架"状态，前端可见

4. 用户浏览/搜索
   ├── 分类浏览 / 关键词搜索 / 筛选
   └── 查看商品详情（图片、评价、规格选择）

5. 用户下单
   ├── 选择 SKU → 加入购物车 → 提交订单
   ├── 库存预留（available -1, reserved +1）
   └── 生成订单（状态：待支付）

6. 用户支付
   ├── 库存扣减（reserved -1, total -1）
   ├── 销量 +1
   └── 订单流转到发货流程
```

## 六、建议的实施分期

| 阶段 | 内容 | 工作量 |
|------|------|--------|
| **第一期**（先做） | 库存流水 + 商品多图 + 价格历史 | 1-2 周 |
| **第二期**（重点） | 库存预警 + 入库/出库单 + 定时上下架 + 标签体系 | 2-3 周 |
| **第三期**（扩展） | 品牌管理 + 供应商管理 | 1-2 周 |
| **第四期**（完善） | 评价管理 + 数据分析 + 搜索优化 | 2-4 周 |
