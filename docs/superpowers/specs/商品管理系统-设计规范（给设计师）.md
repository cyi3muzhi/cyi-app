# 商品管理系统 — UI/UX 设计规范

> 本文档供 UI/UX 设计 AI 使用，定义商品管理系统的**设计原则、页面结构、交互逻辑**。
> 数据库和 API 设计仅供参考，帮助理解数据关系，设计 AI 的重点是**前端界面**。

---

## 一、系统定位

这是一个**后台商品管理系统**，使用群体是**运营人员**。

系统目标是让运营能高效地管理商品的全生命周期——从录入商品信息、配置规格、管理库存，到上架销售和售后评价。

**核心关键词**：高效、清晰、容错、可追溯

---

## 二、整体页面结构

采用后台管理系统常见的**左侧导航 + 右侧内容区**布局。

### 左侧导航

```
商品管理
├── 商品列表（默认页）
├── 商品发布（创建商品）
├── 商品分类
├── 品牌管理
├── 库存管理
│   ├── 库存概览
│   └── 库存流水
├── 评价管理
└── 供应商管理
```

### 每个页面通用要素

- **顶部栏**：面包屑导航 + 搜索框 + 操作人信息
- **内容区**：根据页面不同采用表格/表单/卡片/详情等布局
- **侧边栏可收起**：运营需要更大工作区域时可收起

## 三、页面级设计

### 3.1 商品列表页（默认首页）

这是运营**使用频率最高**的页面。

**页面结构**：

```

│  商品列表                                    [+ 新建商品]   │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ [全部] [销售中] [已下架] [草稿]  │ 搜索框 │ [筛选] │    │ │
│  ├─────────────────────────────────────────────────────────┤ │
│  │ □ │ 商品名称 │ SKU数 │ 价格区间 │ 库存 │ 销量 │ 状态 │  │ │
│  ├─────────────────────────────────────────────────────────┤ │
│  │ □ │ [图] 纯棉T恤 │ 3 │ ¥69-99 │ 235 │ 1,280 │ ● 销售中│ │
│  │ □ │ [图] 牛仔裤  │ 5 │ ¥129-199│ 88  │ 560  │ ● 销售中│ │

│  ├─────────────────────────────────────────────────────────┤ │

```

**设计要点**：
- **商品名称左侧显示缩略图**（50x50），方便运营快速识别

- **库存为 0 时标红高亮**，提醒运营补货
- **支持批量操作**：选中多个商品后，底部显示批量操作栏
- **列可自定义显示/隐藏**：运营可以控制自己关心的列
- **支持导出 Excel**

**筛选条件**：
- 按分类（树形下拉选择）
- 按品牌
- 按价格区间
- 按创建时间
- 按标签（新品/热销/推荐）

- **每一步可以随时保存草稿**：运营填到一半有事走开也不怕
- **有规格/无规格切换**：简单商品（一个规格）直接填价格，复杂商品（多规格）自动生成 SKU 矩阵
- **SKU 矩阵支持批量编辑**：选中多行批量改价/改库存
- **右侧/底部固定"保存"按钮**：不用滑到最底部才能保存
- **预览功能**：运营可以提前看到商品在前端的展示效果

## 四、表单设计规范

商品管理涉及大量表单操作，统一规范很重要。

### 4.1 通用规则

| 规则 | 说明 |
|------|------|
| **必填字段标 *** | 创建时必填，编辑时非必填 |
| **实时校验** | 输入完一个字段立即校验，不要等提交 |
| **自动保存草稿** | 编辑时每5分钟自动保存，防止丢失 |
| **离开确认** | 有未保存修改时，离开页面弹确认框 |
| **操作反馈** | 提交成功后显示 Toast 提示，不弹 Alert |

### 4.2 数字输入

- **价格统一使用"元"**，输入框可以带"¥"前缀
- **库存使用整数**，不允许小数
- **大数字显示千分位分隔符**：1,234 而不是 1234

### 4.3 列表操作

- **点击行 = 进入详情页**（不是选中）
- **勾选 = 选中，用于批量操作**
- **右键菜单**：支持右键快速操作（编辑、复制、删除）
- **表格支持排序**：点击表头排序

## 五、交互细节

### 5.1 商品上下架操作

```
上架 → 确认弹窗："确认上架选中的3个商品？" → 成功Toast
下架 → 确认弹窗："下架后用户将无法购买，确认下架？" → 成功Toast
```

- 定时上架需要弹出一个**时间选择器**
- 批量操作时显示**操作进度**：正在处理第 3/10 个...

### 5.2 价格修改

```
改价 → 弹出批量改价面板：
  [按金额调整]   全部 + [___] 元
  [按百分比调整] 全部 + [___] %
  [统一设为]     全部设为 [___] 元
  ↓
  预览修改结果（显示修改前后的对比）
  ↓
  填写调价原因：[_________] → 确认
```

每次改价**必须填写调价原因**，用于追溯。

### 5.3 库存操作

```
入库 → 填写入库单 → 确认后库存立即更新 → 自动记录流水
出库 → 填写出库单（如果是销售出库，关联订单号）→ 确认
```

库存操作**不可撤回**，所以要加二次确认弹窗。

### 5.4 加载与空态

- **列表加载**：首次显示骨架屏，刷新显示顶部加载条
- **空状态**：不要只显示"暂无数据"，要引导操作
  - 商品列表为空 → "还没有商品，[去发布第一个商品]"
  - 搜索结果为空 → "没有找到匹配的商品，试试其他关键词"
  - 评价为空 → "暂时没有评价"

## 六、颜色系统

后台系统不需要花哨，但要清晰传达信息状态。

```
主色（品牌色）：    #1890FF  蓝色  — 按钮、链接、选中态
成功（上架/正常）： #52C41A  绿色  — 状态标签、成功提示
警告（预警）：     #FAAD14  橙色  — 库存预警、待处理
```

## 七、响应式要求

虽然是后台系统，但运营可能会在平板上操作：

- **最低宽度 1280px**（不要低于这个，否则表格太挤）
- **1920px+ 自适应**：大屏可以显示更多列、更宽的内容区
- **表格列支持固定**：商品名称列固定，其他列可横向滚动
- **侧边栏可收起**：小屏时自动收起为图标

## 八、移动端（H5）特殊说明

如果后续要迁移到手机端，需要注意：

- 商品列表 → 改为**卡片流式布局**，而不是表格
- 创建商品 → 改为**分步表单**，每一步一屏
- 详情页 → Tab 改为**横向滑动切换**
- 库存操作 → 简化流程，一个页面完成
- 评价管理 → 列表点赞式交互

## 九、设计原则总结

```
1. 信息层级清晰     → 最重要的信息放在最显眼的位置
2. 操作路径最短     → 最常用的操作不需要进入详情页
3. 容错性高         → 危险操作有二次确认，修改有历史记录
4. 状态可见         → 商品状态、库存状态、操作状态一目了然
5. 批量优先         → 运营经常需要批量操作，支持勾选后批量处理
6. 性能感知         → 加载中要有反馈，长时间操作要显示进度
7. 引导代替报错     → 空状态、搜索无结果时引导用户下一步操作
```
